# Adaptive multiresolution DWT action tokens for π₀-FAST

Implementation of [`../adaptive_dwt_vla_experiment_spec.md`](../adaptive_dwt_vla_experiment_spec.md): a LeRobot
policy plugin (`adaptive_dwt`) that fine-tunes `lerobot/pi0fast-base` to emit a grammar-constrained stream of
segment-length / resolution / Haar-coefficient / gripper-event tokens instead of FAST DCT+BPE tokens, plus the
matched FAST baseline, offline codec evaluation, training, closed-loop LIBERO evaluation and a live dashboard.

Results: [`results/offline_codec_report.md`](results/offline_codec_report.md) (Stage A) and
[`results/summary.md`](results/summary.md) (Stages B–D). Everything in `results/` is generated by the scripts
below; nothing is hand-entered.

## Layout

```
src/lerobot_policy_adaptive_dwt/
  token_grammar.py   302-token vocabulary, Segment, GrammarFSM (allowed-token masks, parse/serialize)
  codec_basis.py     orthonormal Haar matrices (pywt, periodization), coefficient groups
  quantizer.py       per (segment length, group, dim) 256-bin uniform quantizer, exact zero for details
  codec.py           AdaptiveDWTCodec: encode_plan / decode / segment candidates / fixed plans
  oracle_dp.py       DP oracle over segmentations x resolutions (alpha*SSE + beta*vel SSE + gamma*tokens)
  configuration_adaptive_dwt.py, processor_adaptive_dwt.py, modeling_adaptive_dwt.py
                     PI0Fast subclasses (upstream pi0_fast is not modified), constrained KV-cached decoder,
                     LoRA + action-row adapters, adapter-only checkpoints
scripts/
  prepare_libero.py      episode index + per-task 90/10 episode split (seed 0)
  evaluate_codec.py      Stage A (codec_metrics.csv, Pareto plots, example streams)
  train.py               Stages B/C (fast_matched | dwt_fixed | dwt_adaptive)
  check_overfit_decode.py Gate 2: generated streams of an overfit checkpoint == oracle streams
  evaluate_policy.py     Stage D closed-loop LIBERO, Wilson CIs, videos, results/eval.json
  run_pilot.sh           Stage C+D queue (train to 2k -> eval -> resume to 5k -> eval)
  write_reports.py       results/offline_codec_report.md and results/summary.md from measured files
tests/                   61 CPU tests (codec, grammar, oracle) + 4 GPU tests (loss/gradients/checkpoints)
```

## Training recipe and memory policy

- Frozen BF16 backbone (vision tower fp32 as upstream); trainable: LoRA r=16 on q/k/v/o/gate/up/down in all 18
  Gemma layers + untied residual rows for the action vocabulary in `embed_tokens` and `lm_head`
  (20.85M params for DWT, 23.81M for FAST, which needs 1026 action rows instead of 302).
- Loss: full-vocabulary next-token cross-entropy on `Action: <stream> <end>` exactly as upstream π₀-FAST;
  per-class accuracy/loss (LEN, RES, coef, gripper, end) is logged for the DWT variants.
- Windows never cross an episode end; normalization statistics come from the training episodes of the selected
  tasks; the DWT quantizer is calibrated on those same training windows.
- Fastest measured setting on the A6000: no gradient checkpointing, second camera slot disabled
  (`--empty-cameras 0`, numerically identical because empty cameras are fully masked), micro-batch 8.
  `--grad-ckpt` brings VRAM to ~14 GB at ~1.8x the step time.

**Checkpoints are adapter-only** (the 5.8 GB backbone is never copied): per run `ckpt/latest` (adapters +
optimizer, overwritten, ~250 MB), `ckpt/best` (lowest val loss, overwritten, ~83 MB), and one `ckpt/step_XXXXX`
per `--milestones` entry (~83 MB). A pilot run therefore uses ~0.5 GB. Saving is atomic (temp dir + rename) and
refuses to write when less than `--min-free-gb` (default 15 GB) is free.

## Dashboard

The smooth-operator web app serves `/experiments`: run cards (state, progress, ETA, s/step, VRAM, GPU-hours,
checkpoint sizes, free disk), training/validation loss curves (log-scale toggle), per-token-class accuracy and
loss, throughput, evaluation table with Wilson intervals, codec tables, result plots and the summary. It reads
`runs/*/status.json`, `runs/*/metrics.jsonl` and `results/` and refreshes every 10 s.

## Released weights and training report

`weights/<run>_step_XXXXX/` holds the final adapter checkpoint of every learning-curve run (step 2000), pilot
run (step 5000) and step-2000 follow-up (DCT without BPE, sym4→haar, and the `dwt_fixed_lw` / `dwt_fixed_slw` loss
variants, which train the same Haar tokens with `--soft-sigma` soft labels and/or quantizer-step weighting): `adapters.safetensors` (LoRA + action-row adapters, Git LFS) and `meta.json` (codec, norm stats,
base-model revision). Run `git lfs install && git lfs pull` after cloning, then load with
`load_checkpoint("weights/lc_s2_dwt_fixed_step_02000")`; the frozen base model comes from Hugging Face.

The full-LIBERO policies (all 40 tasks, one epoch = 14,500 steps) are under `weights/full_*`: Haar DWT fixed after
epochs 1–3 (`full_s0_dwt_fixed_slw_step_{14500,29000,43500}`), the three epoch-4 branches from the epoch-3 checkpoint
(`full_e4_{dwt_fixed,dwt_fixed_lw,dwt_fixed_slw}_step_58000`), and the DCT-without-BPE control after each epoch
(`full_s0_dct_fixed_step_*`, added as `scripts/run_full_dct_control.sh` finishes), plain Haar from scratch
(`full_s0_dwt_fixed_step_*`), DCT with √step weighting one epoch from DCT epoch 2 (`full_e3_dct_fixed_sqrtw_step_43500`)
and from scratch (`full_s0_dct_fixed_sqrtw_step_{14500,29000}`), and orthogonal-polynomial tokens (`--variant poly_fixed`) with
the same weighting (`full_s0_poly_fixed_sqrtw_step_{14500,29000,43500}`; epoch 3 reaches 92.8% on all 40 tasks). `train.py --weight-power p` weights coefficient-token losses
by quantizer step ** p for any DWT/DCT/polynomial variant. Every intermediate checkpoint of these runs stays in `runs/`
and is mirrored to the data partition; success per epoch is in section 7b of the report.

`../reports/training_report.html` is a self-contained report (setup, compute, curves, closed-loop success, released
weights, wavelet choice), rebuilt from `runs/` and `results/` by `python scripts/write_training_report.py`;
`../reports/wavelet_selection.html` (offline comparison of 26 wavelet transforms) by `python scripts/wavelet_selection.py`;
`../reports/transform_shift_analysis.html` (synthetic: how many tokens a visible edit of a smooth motion shifts under 18
transforms) by `python scripts/transform_shift_analysis.py`; `../reports/transform_fingerprint_analysis.html` (whether
different edits leave distinct token patterns) by `python scripts/transform_fingerprint_analysis.py`;
`../reports/transform_topk_shift_analysis.html` (top-3% coefficient shift) by `python scripts/transform_topk_shift_analysis.py`;
`../reports/transform_polynomial_variants.html` (polynomial & spline bases) by `python scripts/transform_polynomial_variants.py`;
and `../reports/experiment_trail.html` (chronological experiment graph) by `python scripts/write_experiment_trail.py`. `runs/`, `data_cache/`,
rollout videos, logs and dataset-derived example plots are not committed.

## Known limitations

- H=32 Stage A uses 783 disjoint validation windows (< 1000 requested): that is all the validation episodes hold.
- The pilot is one task, one seed, 20 rollouts per model: enough to debug and to see large effects, not to rank
  tokenizers. `ref_*` LeRobot checkpoints are full fine-tunes on all 40 LIBERO tasks and are not a matched
  comparison.
- Our decoder feeds `BOS` + `Action: ` causally exactly as in training; upstream π₀-FAST's KV decoding appends BOS
  to the language prefix instead. Both FAST and DWT pilot variants use our decoder.
- Data order is reshuffled when a run resumes (optimizer, schedule and counters are restored).
